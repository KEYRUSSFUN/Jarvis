# Jarvis

Командный проект. Репозиторий приватный: доступ есть только у участников команды.

Локальный голосовой ассистент для Windows: держите горячую клавишу и говорите команду —
Jarvis распознаёт речь (faster-whisper), решает, что сделать (Qwen3 через Ollama),
выполняет действие и отвечает голосом (Silero TTS). Всё работает без интернета.

## Запуск

Нужны Windows 10/11, Python 3.11+, [uv](https://docs.astral.sh/uv/) и
[Ollama](https://ollama.com). Видеокарта NVIDIA желательна (проверено на RTX 4060, 8 ГБ),
без неё распознавание пойдёт на CPU медленнее.

```
ollama pull qwen3:8b
setx OLLAMA_KV_CACHE_TYPE q8_0     # 8-битный кэш контекста, затем перезапустите Ollama
setx OLLAMA_FLASH_ATTENTION 1      # (значок в трее → Quit и запустить снова)
uv sync --extra gpu      # без видеокарты NVIDIA: uv sync
uv run jarvis            # или: uv run jarvis --dry-run — команды только пишутся в лог
```

8-битный кэш нужен для памяти разговора: окно в 4096 токенов с обычным кэшем вместе
с распознаванием речи не помещается в 8 ГБ, и ответы замедляются в 2–5 раз. Без этих
переменных поставьте `num_ctx = 2048` в разделе `[llm]` файла `config.toml` — памяти будет меньше.

При первом запуске скачиваются модели распознавания (~1,6 ГБ) и озвучки (~90 МБ, в `models/`).
Держите горячую клавишу (`hotkey` в `config.toml`) и говорите; отпустили — Jarvis отвечает
«Да, сэр» и выполняет. Нажатие во время ответа обрывает речь. Опасные действия (выключение,
перезагрузка) он сначала переспросит.

Jarvis помнит разговор: «Открой блокнот» → «Закрой его», «Меня зовут Кирилл» → «Как меня
зовут?». После 5 минут тишины разговор начинается заново (`memory_minutes` в `config.toml`).

Настройки — в `config.toml`: горячая клавиша, модели, голос, свои названия для приложений.
Лог с временем каждого шага — `logs/jarvis.log`.

## Что умеет

| Инструмент | Пример команды |
|---|---|
| `open_app`, `close_app` | «Открой телеграм», «Закрой блокнот», «Закрой Steam» (и программы в трее) |
| `open_file` | «Открой отчёт», «Открой файл список покупок» |
| `type_text` | «Напечатай привет, как дела», «Напиши в нём: совещание в пятницу» |
| `press_keys` | «Сохрани» (ctrl+s), «Нажми энтер» |
| `set_volume`, `change_volume`, `mute`, `unmute` | «Громкость 50», «Потише», «Выключи звук» |
| `media_control` | «Пауза», «Следующий трек» |
| `open_url`, `web_search` | «Открой ютуб», «Найди рецепт блинов» |
| `get_datetime`, `system_info` | «Который час?», «Как загружен процессор?» |
| `power` (с подтверждением) | «Перезагрузи компьютер» |

Программу без окна (в трее), которая не закрылась по просьбе, Jarvis через ~3 с завершает
принудительно; программы с открытым окном закрываются только как крестиком. Пока Jarvis печатает,
переключение на другое окно или нажатие Ctrl, Alt или Win (горячая клавиша по умолчанию — левый Ctrl)
останавливает печать.

## Тесты

```
uv run pytest            # быстрые тесты, без моделей
uv run pytest -m llm     # команды tests/commands.yaml и диалоги tests/dialogs.yaml через настоящую модель
```

Набор команд — проверка связки «модель + промпт + описания инструментов», диалоги — проверка памяти.
Прогоняйте его после любой правки промпта, описаний инструментов или смены модели.

## Устройство

```
src/jarvis/
  app.py          главный цикл: клавиша → запись → распознавание → агент → озвучка
  agent.py        цикл агента: LLM → инструменты → LLM, до 5 шагов
  safety.py       единственная дорога к инструментам: проверка аргументов, подтверждение, dry-run
  llm.py          потоковый клиент Ollama
  prompts.py      системный промпт
  config.py       config.toml
  dialog.py       разбор ответа «да / нет»
  audio/          запись по клавише, распознавание, озвучка, подготовка текста к озвучке
  tools/          инструменты; каждый объявляет уровень риска в реестре
```

Новый навык — функция с декоратором `@registry.tool(...)` в модуле `tools/` плюс команды
для него в `tests/commands.yaml`.

## Как работаем

1. Склонировать репозиторий:

   ```
   git clone https://github.com/KEYRUSSFUN/Jarvis.git
   cd Jarvis
   ```

2. Создать свою ветку (имя — свой логин на GitHub) и работать только в ней:

   ```
   git checkout -b <логин>
   git push -u origin <логин>
   ```

3. Перед работой подтянуть свежие изменения из `main`:

   ```
   git pull origin main
   ```

4. Фиксировать изменения и отправлять их в свою ветку:

   ```
   git add <файлы>
   git commit -m "Что сделано"
   git push
   ```

5. Когда версия рабочая — открыть Pull Request из своей ветки в `main`.
   После проверки его вливают в основную ветку.

# Jarvis: управление программами и файлами — дизайн

Этап 2, часть «программы и система». Браузер — отдельная следующая задача.

## Зачем

Сейчас Jarvis умеет только запускать приложения из меню «Пуск» и закрывать видимые окна.
Пользователь не может голосом:

- закрыть программу, которая живёт в трее без окна (Steam, Wallpaper Engine);
- открыть обычный файл с рабочего стола («Отчёт.docx») и написать в нём текст;
- выполнить простое действие в открытой программе («сохрани», «новая вкладка»).

Цель — сделать Jarvis заметно универсальнее на той же локальной модели (qwen3:8b через Ollama,
без облака, без интернета).

## Цели

1. **Открыть файл или папку** по названию: «Открой отчёт» → `Отчёт.docx` в программе по умолчанию.
2. **Напечатать текст** в нужном окне: продиктованный дословно или сочинённый моделью.
   «Напиши в нём…» после «Открой отчёт» — память разговора подсказывает, что «в нём» = окно отчёта.
3. **Нажать сочетание клавиш** в нужном окне: «Сохрани» → Ctrl+S, «Новая вкладка» → Ctrl+T.
4. **Закрыть программу из трея**: если видимого окна нет, найти запущенный процесс по названию,
   попросить закрыться, через ~3 с завершить принудительно.
5. **Запуск по ярлыку**: `open_app`, не найдя приложение в «Пуске», ищет ярлык на рабочем столе
   («Запусти Warframe» → `Warframe.url`).

## Не цели

- Браузер: чтение страниц, клики, формы — следующая задача.
- Клики по кнопкам и меню внутри программ (UI Automation).
- Выполнение произвольных команд системы (PowerShell, cmd).
- Облачные модели.

## Анти-цели (провал, даже если «работает»)

- Текст напечатан не в то окно. Если нужное окно не удалось сделать активным — **не печатать**,
  честно сказать, что не вышло.
- Закрыто что-то важное: системный процесс, Проводник, Ollama, сам Jarvis.
- Принудительно завершена программа с открытым окном (потеря несохранённого). Программы
  с видимыми окнами закрываются только «вежливо» (WM_CLOSE — как крестик).
- Нажатия, которые Jarvis делает сам (Ctrl+S), воспринимаются им как горячая клавиша
  и обрывают его речь или запускают запись.
- Регресс набора `tests/commands.yaml` и `tests/dialogs.yaml` (сейчас 50 из 51; единственный провал —
  «Включи звук обратно», был до этой работы).

## Ограничения

- Windows 10/11, Python 3.11+, без новых зависимостей: ctypes (WinAPI), psutil, pynput 1.8.2 — уже есть.
- Модель локальная и небольшая: инструментов немного, описания короткие и однозначные,
  логика выбора — в коде, а не в промпте. Любая правка промпта/описаний — с прогоном `uv run pytest -m llm`.
- Скорость: новые инструменты не добавляют задержки к командам, которые их не используют.
  Поиск файлов — доли секунды.
- Рабочий стол пользователя перенесён в OneDrive (`C:\Users\…\OneDrive\Рабочий стол`):
  папки находить через Known Folders API (`SHGetKnownFolderPath`), а не `~/Desktop`.

## Решения

### Инструменты для модели

| Инструмент | Параметры | Что делает |
|---|---|---|
| `open_file` | `name` | Ищет файл/папку/ярлык по похожему названию и открывает программой по умолчанию |
| `type_text` | `text`, `window` (необяз.) | Делает окно `window` активным (если задано) и печатает текст в позицию курсора |
| `press_keys` | `keys`, `window` (необяз.) | То же, но нажимает сочетание: `ctrl+s`, `ctrl+shift+t`, `enter`, `f5` |
| `close_app` | `app` | Как раньше для видимых окон; если окна нет — закрытие процесса (см. ниже) |
| `open_app` | `app` | Как раньше; если нет в «Пуске» — ярлык на рабочем столе; затем браузер по умолчанию |

### Поиск файлов (`open_file`)

- Папки: рабочий стол пользователя, общий рабочий стол, «Документы», «Загрузки».
  Верхний уровень и один уровень вложенных папок; скрытые и системные пропускаются.
- Кандидаты: файлы (сравнение по имени без расширения), папки, ярлыки `.lnk`/`.url`.
- Сравнение — существующий `find_best` (нечёткий, с транслитерацией, порог 70).
- Открытие — `os.startfile` (как двойной щелчок).
- Ответ: «Открываю Отчёт.» Ошибка без `speech` — модель сама объяснит.

### Печать текста и клавиши (`type_text`, `press_keys`)

- Окно ищется среди видимых окон по заголовку через `find_best` (как `close_app`).
  Если окна ещё нет (Word только запускается после `open_file`) — ждать его появления до ~15 с,
  но только если в последние ~20 с Jarvis что-то запускал (`open_file`/`open_app`); иначе сразу
  ошибка, чтобы промах модели с названием окна не подвешивал Jarvis. *(решение исполнителя-автора)*
- Активация: восстановить, если свёрнуто; обойти запрет Windows на смену фокуса фоновым
  процессом (нажатие неиспользуемой клавиши F24 перед `SetForegroundWindow`; Alt не годится —
  он открывал меню Блокнота, и текст уходил туда); **проверить**, что окно
  действительно стало активным. Не стало — ошибка, ничего не печатаем.
- Без `window` — печать в текущее активное окно.
- Печать — `SendInput` с `KEYEVENTF_UNICODE` (не зависит от раскладки), перевод строки — Enter.
- Текст вставляется в позицию курсора (как печатал бы человек). «В конец» — модель может
  сначала нажать `ctrl+end`.
- `press_keys`: имена клавиш `ctrl`, `shift`, `alt`, `win`, `enter`, `tab`, `esc`, `backspace`,
  `delete`, `home`, `end`, `pageup`, `pagedown`, стрелки, `f1`–`f12`, буквы и цифры; неизвестная
  клавиша — ошибка с перечнем допустимых.
- Слушатель горячей клавиши игнорирует события с флагом `injected` (pynput 1.8: обработчики
  получают `(key, injected)`).

### Закрытие программ в трее (`close_app`)

1. Видимое окно нашлось — как сейчас: WM_CLOSE, приложение само спросит про несохранённое.
2. Нет — поиск среди процессов текущего пользователя по названиям: имя exe без расширения,
   «Описание» и «Продукт» из версии файла, имя папки программы (`wallpaper_engine` → «wallpaper engine»).
3. Защищены и не рассматриваются: всё из `C:\Windows`, `explorer`, процессы Ollama, сам Jarvis
   и его родители.
4. Закрываются все процессы с тем же exe, что у найденного, начиная с корневых (родитель — не этот
   exe), вместе с дочерними *(решение автора: у Steam десятки процессов)*. Сначала WM_CLOSE во все их
   окна, включая скрытые; ждать до ~3 с; живы — `kill`. Нет прав (процесс от администратора) — ошибка.
5. Процесс с видимым окном принудительно не завершается никогда.
6. Подтверждение не спрашивается.

### Модель и промпт

- Описания новых инструментов — короткие, с примерами фраз; правило в промпте — не больше
  одной строки на инструмент и только если без него проваливаются проверки.
- В `tests/commands.yaml` добавить команды на новые инструменты, в `tests/dialogs.yaml` —
  диалоги: «Открой отчёт» → «Напиши в нём привет»; «Открой блокнот» → «Напиши список покупок» → «Сохрани».

## Оставлено исполнителю

- Точные тексты описаний инструментов и ответов (`speech`), структура модулей в `tools/`.
- Как именно реализовать ожидание окна и проверку активности (опрос с шагом ~100 мс — ок).
- Чтение версии файла (WinAPI `GetFileVersionInfoW` через ctypes) и кэширование.
- Тесты: логика выбора (поиск файлов, разбор клавиш, выбор процесса, защита) — юнит-тестами
  с подменой backend'а, как сейчас в `tests/test_tools.py`; WinAPI — проверка руками/скриптом.
